# 用 Go 自研解析，不基于 tshark，不依赖 libpcap

tshark 能解析 HTTP，但不适合长时间实时检索。处理一个 770MB 的抓包，它的峰值内存达到 4.6GB，而且抓包越大占用越高；用 `-M` 定期清空状态，又会丢掉正在进行的交互。它也不会把请求和响应配成一对输出，而且得先装到生产服务器上。因此 httpgrep 自己做 TCP 重组和 HTTP/1.x 解析：直接读 tcpdump 写出的 pcap 数据流，不链接 libpcap，用 Go 编译成 linux/amd64 静态单文件，拷到服务器上就能运行。

## 考虑过的方案

- 在 tshark 外面包一层（Python 或 Shell）：开发最快，HTTP/2 解析、TLS 解密、body 解压都是现成的，但有上面说的内存和部署问题。
- Rust：内存控制更精确，也没有 GC 停顿，但交叉编译要额外准备工具链，开发周期更长。按现有流量，Go 的性能已经够用。
- C/C++：要解析的是不可信的网络数据，内存安全风险太大。

## 后果

- 内存上限只能管住缓存的抓包数据。进程实际占用还要加上 Go 运行时的开销，做不到精确到字节。
- tshark 自带的 HTTP/2 解析、TLS 解密、body 解压，都要自己实现。
